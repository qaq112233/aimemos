# 功能约定

本文件描述 v0.2.0 已实现的行为及保留边界。具体部署步骤见[主文档](../README.md)，开发验证见[开发说明](DEVELOPMENT.md)。

## 访问与用户

- 两种模式启动都需要显式配置允许用户：用户名、正整数 Telegram 用户 ID，或二者的并集。
- 支持 `ALLOWED_USERNAMES`、`ALLOWED_USER_IDS`，兼容 `TELEGRAM_USER_ID` 及旧 YAML 的 `user_id_env`。
- 不配置或配置无效时拒绝启动；默认不开放任何人。仅在某一项单独手动填写小写 `none`、其他项为空时开放所有人。
- 消息和按钮使用同一访问规则。AI 笔记模式只接受发送人自己的私聊，各用户的素材、草稿、模型选择和按钮按用户隔离。
- AI 笔记模式共用配置的 Memos 令牌；即时保存模式按 Telegram 用户保存各自绑定的 Memos 令牌。

## 素材和草稿

- 连续发送或转发的文字、网址、照片、相册和文件加入当前用户的同一组素材，顺序按接收顺序。
- 未选择处理方式前，不调用 AI、不创建 Memos、不上传附件。四秒状态节流不触发分组或保存。
- 数字入口集中配置，精确匹配本人发送的纯文字；转发或图片说明中的数字作为素材。
- 原样保存按顺序合并原文、说明和来源；简单整理不默认压缩成摘要；教程与图片方案将无法确认的内容标记“待确认”。
- 草稿状态的普通文字作为修改要求，通过“补充素材”回到收集状态。多轮生成保留当前草稿和编辑要求。
- 每次生成使用素材快照，生成期间收到的新素材不混入本次结果。保存较早快照后保留未纳入素材。

## 图片与模型

- 支持显式选择供应商、模型、协议与整理方案；支持 Responses 和 Chat Completions，不自动切换或降级。
- 模型声明图片能力且方案启用读图时才发送图片数据；不支持时明确提示，不静默省略。
- 图片按需下载，AI 输入包含图片数据及素材、附件索引，不包含 Telegram 文件标识或带 Bot Token 的内部下载地址。
- 支持 PNG、JPEG、WebP、GIF，按实际内容判断格式。单文件下载上限 20 MiB，默认单次生成最多八张。
- 用户可以选择原样保存、简单整理、教程整理、自定义整理和图片理解；入口数字、提示词和标签词表可配置。
- AI 只生成 Markdown，不直接操作 Memos。重要图片信息进入正文或图注；网址只保留链接与附带说明，不抓取网页正文。
- 模型默认、方案覆盖与本次参数依次覆盖；思考、输出上限及供应商扩展按显式配置发送，保留字段不能用于替换输入或启用工具与服务端会话。

## 保存与失败恢复

- 除原样保存外，写入 Memos 前必须确认具体版本的完整草稿；旧按钮、重复确认和其他用户的按钮不会重复创建正文。
- 截断或不完整输出不得确认保存。AI 失败保留素材、已有草稿和修改要求。
- 保存正文后上传附件，部分失败只重试失败附件；补传期间保留笔记标识。
- 同一用户保存或待补传期间不接收新素材，提示完成后重发。其他用户的独立素材组可以继续操作。
- 标签与正文同次生成并确认，默认通常二至五个，可更少；原样保存不新增 AI 标签。
- 网络中断可能使写入结果不确定；重试前检查 Memos，不承诺跨重启去重。

## 数据与范围

素材、草稿、编辑要求与补传进度只放内存，重启即丢失。保存成功或放弃后清理对应素材组。绑定文件和已保存的 Memos 数据需要持久化。

当前不包含网页正文抓取、QQ/钉钉接入、数据库草稿恢复、向量检索、自动模型路由或复杂正文插图。未来索引可从 Memos 已保存内容重建，Memos 始终是笔记来源。
